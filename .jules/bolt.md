## 2025-05-14 - [Vectorized Context Addition] **Learning:** Vectorizing the addition of resource context (IDs, names, dates) by combining data frames first and then adding columns to the result is ~150x faster than iterative `mutate` calls for large datasets (e.g., 400 resources). However, when mapping metadata back to rows, `POSIXct` vectors extracted from named vectors retain names which causes `expect_identical` to fail in tests against original data. **Action:** Use `names(x) <- NULL` after extracting metadata via subsetting to ensure clean data frames.

## 2025-05-14 - [Redundant Date Parsing] **Learning:** `as.POSIXct` is surprisingly expensive when called on thousands of repeated strings in a large data frame. Pre-parsing unique date strings from resource metadata *before* expansion/recycling is essential for performance in context enrichment. **Action:** Use `unique()` and `stats::setNames()` to create a mapping of unique strings to `POSIXct` objects before vector expansion.

## 2025-05-14 - [Vectorized Record Parsing] **Learning:** In `get_resource_sql`, the iterative `purrr::map` + `tibble::as_tibble` loop for record processing is a major bottleneck (N+1-like overhead). `dplyr::bind_rows()` can handle a list of lists (records) directly and is significantly faster. **Action:** Bind records first, then apply targeted vectorized operations (like `is.na` replacement) only to columns that require it.
